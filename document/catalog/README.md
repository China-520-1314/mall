## 推荐系统如何使用新增数据

新增商品是普通已上架商品，具有正确的分类和品牌 id，自动进入现有个性化推荐候选集。同时加入新品和首页推荐表，并交错排列不同分类，使首页能展示多种商品。

推荐仍根据分类偏好、品牌偏好及真实销量排序。行为来源扩充为：浏览权重 2、购物车权重 4、收藏权重 5、已付款/已发货/已完成订单权重 8；购物车和订单按当前会员过滤，各取最近 30 件不同商品，取消或待付款订单不计入购买偏好。MongoDB 不可用时，浏览/收藏偏好暂不可用，但仍根据 MySQL 中的购物车与订单推荐。没有任何行为时维持原有按销量排序的结果，不伪造销量来提升新品排名。

演示方法：登录后加入几件同类商品到购物车，再回到首页查看“猜你喜欢”；例如加入冰箱后，同类的新增冰箱会参与排序。浏览与收藏本身的持久化仍需原项目的 MongoDB 服务。

## 重新导入

项目根目录运行（Python 需要 beautifulsoup4、Pillow；数据库需要 mysql、mysqldump 客户端）：

```powershell
# 使用仓库已保存的资料及图片；密码读取 MALL_DB_PASSWORD 或 MALL_DATASOURCE_PASSWORD。
python scripts/catalog/import_catalog.py              # 仅生成 SQL，供审查
python scripts/catalog/import_catalog.py --apply      # 先备份，再事务导入
python scripts/catalog/verify_catalog.py              # 后端启动后验证商品、规格、图片及推荐候选集
```

可审查的 SQL 为 `document/sql/mall_catalog_mi_20260911.sql`。导入按 `WEB-MI-20260911-官方商品ID` 商品编号去重，再次执行不会覆盖已有商品的价格、库存或已生成订单。导入脚本会先核对品牌、分类和本地图片 SHA-256；任何 SQL 失败都会终止本次事务。备份只包含受影响的商品、属性和首页推荐表，位于 `output/catalog-backup/时间/catalog-before.sql`，不包含会员密码。

默认图片地址为 `http://localhost:8085`。如后端地址变化，初次导入前通过 `--image-base-url` 指定正确地址；已经导入的数据不会被重复导入覆盖，应在管理端或明确的数据迁移中调整。

若需重新采集，保存最新小米商城首页为 `output/mi-shop.html` 后运行 `python scripts/catalog/prepare_catalog.py`、`scripts/catalog/download_images.ps1`、`python scripts/catalog/prepare_catalog.py --images`。当前批次编号固定为 `20260911`；为新日期创建新批次，不要用新来源覆盖本批次记录。
